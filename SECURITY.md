# Security Policy

Thank you for helping keep SecureScan safe! We take the security of our platform and our users seriously.

## Supported Versions

Security updates are provided for the following versions of the project. Please ensure you are running a supported version before submitting a report.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.6   | :white_check_mark: |
| < 1.0   | :x:                |


## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.** 

If you discover a security vulnerability within SecureScan, please send an email to **vishal@hacksudo.com]**.

When reporting a vulnerability, please include the following information:
* A description of the vulnerability and its impact.
* Steps to reproduce the vulnerability (including any relevant payloads or screenshots).
* The version(s) of SecureScan where this vulnerability was observed.
* Any possible mitigations you might suggest.

### Response Timeline
We will acknowledge receipt of your vulnerability report within **48 hours** and strive to send you regular updates about our progress. 

If the vulnerability is accepted, we will:
1. Develop a patch.
2. Test the patch to ensure it resolves the issue without breaking existing functionality.
3. Release a new version with the security fix.
4. Publish a security advisory crediting you for the discovery (if you wish to be credited).

## Scope

The following areas are strictly **out of scope** for vulnerability reports:
* Issues requiring physical access to the server running the application.
* Social engineering or phishing attacks against users or maintainers.
* Denial of Service (DoS) attacks that rely on volumetric traffic (unless caused by an easily exploitable application logic flaw).

Thank you for your responsible disclosure!
